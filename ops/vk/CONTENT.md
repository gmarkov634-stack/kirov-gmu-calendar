## Правила публикаций и изменений

- Перед новой публикацией сначала показать пользователю полный черновик и публиковать только после явного подтверждения.
- Перед изменением metadata сообщества показать точный diff «было → станет» и менять только согласованные поля.
- Не сообщать, что расписание текущего периода доступно, пока соответствующая группа не прошла source-bound review, canonical QA и фактическую публикацию.
- Не помещать изменяемую цену в вечнозелёный закреп, описание сообщества или образовательные публикации.
- Новые текстовые посты production-подтверждены через GitHub OIDC control plane с `wall.post`.
- Автоматическую публикацию **wall-поста с изображением** нельзя считать поддерживаемой текущими VK credential classes. Изображение к уже созданному посту при необходимости прикрепляется вручную в интерфейсе VK и затем проверяется read-only `wall.list`.
- `group.info` разрешён как read-only команда.
- `group.edit` production-подтверждён только для строгого allowlist `description` и `website`.
- Закрепление и удаление существующих постов при текущих токенах остаются ручными действиями VK.
- Operational PR с `ops/vk/command.json` закрывается без merge после выполнения команды.
