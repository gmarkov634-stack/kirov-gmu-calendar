# O72 — Weekday-заголовок в `course_lecture_list` является наследуемым контекстом секции

## Область применения

Только профиль `course_lecture_list`.

## Правило

Однозначный заголовок дня недели (`ПОНЕДЕЛЬНИК`, `ВТОРНИК`, `СРЕДА`, `ЧЕТВЕРГ`, `ПЯТНИЦА` и иной явно поддержанный weekday) задаёт `structural_weekday` для последующих обычных лекционных `source_series` до следующего weekday-заголовка либо явной границы `source_part`.

Пустые строки, несколько последовательных лекционных записей и физические переносы внутри одной записи по O66 не сбрасывают этот контекст. Каждая серия при этом остаётся независимой по O68: weekday используется для разбора и проверки её собственного `date_expression`, а не для объединения соседних строк.

Явная специальная семантика конкретной строки имеет приоритет. Подтверждённая строка `*hh.mm–hh.mm ...` вне weekday-секции обрабатывается по O31 и не получает последний встреченный weekday только из-за текстовой близости. Если принадлежность строки к weekday-блоку нельзя установить однозначно, применяется fail-closed `needs_review`.

## Подтверждённый пример

Русский `4lek.pdf`: после заголовка `ПОНЕДЕЛЬНИК` последовательно идут самостоятельные записи:

- `Неврология, медицинская генетика, нейрохирургия`;
- `Акушерство и гинекология`;
- `Педиатрия`;
- `Факультетская хирургия, урология`.

Все эти записи наследуют понедельник до следующего заголовка `ВТОРНИК`. Пустая строка между записями не меняет weekday-контекст.

## Реализация

Исторический `fourth-parser.mjs` уже хранит текущий weekday как section state: weekday меняется только при встрече нового weekday-заголовка. O72 поэтому не требует отдельного изменения parser logic для подтверждённого текущего паттерна; поведение закрепляется regression-тестом. Это не означает, что универсальная геометрическая проверка неоднозначных границ weekday-секций уже полностью реализована.
