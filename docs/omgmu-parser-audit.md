# ОмГМУ — аудит PDF-парсеров

## Статус

Исторические PDF-парсеры ОмГМУ проаудированы как основа для расширения на 2026/27. Они сохраняются как regression/reference, но не считаются универсальными production-профилями.

## Вывод

Существующие парсеры ориентированы преимущественно на программу `medicine-international`, весенний семестр 2025/2026 и конкретные структуры PDF. В них присутствуют жёстко зашитые 2026 год, праздничные даты, `semester=2`, `academicYear=2025-2026`, offset `+06:00`, а в отдельных модулях — конкретные группы 485/486/585. Эти ограничения несовместимы с целевой мультивузовской архитектурой и canonical `schedule-batch/v1`.

## Инвентаризация

### weekly-parser.mjs / weekly-parser-blocks.mjs

Полезная модель недельного табличного PDF: дни недели задают блоки строк, группы расположены по столбцам, ячейки содержат время, дисциплину и диапазон/перечень дат.

Сохраняем:
- детекцию колонок групп;
- разделение времени и дат;
- разворачивание диапазона по указанному дню недели;
- deduplication как диагностическую идею.

Не переносим напрямую:
- `HOLIDAYS_2026`;
- фиксированный 2026 год;
- `program=medicine-international`;
- `academicYear=2025-2026`, `semester=2`;
- генерацию старых event id;
- timestamp с `+06:00`.

### fourth-parser.mjs

Source-specific прототип 4 курса иностранных обучающихся. Умеет раздельно читать лекции и цикловые занятия, но цикловая часть жёстко привязана к колонкам групп `485` и `486`.

Решение: сохранять только как исторический fixture/reference. Не использовать как универсальный профиль.

### cycle-parser.mjs

Source-specific прототип 5 курса иностранных обучающихся, группа `585`. Разбирает блоки дисциплина + время + диапазон с пометкой «лекции/циклы» и разворачивает рабочие дни.

Решение: сохранять только как fixture/reference. Общую идею циклового профиля можно переиспользовать после проверки на новых официальных PDF.

## Базовые правила

- O01: один PDF может содержать несколько логических частей; source anchor/part сохраняется отдельно.
- O02: при русско-английском дубле одна и та же учебная информация не дублируется в событиях; приоритет русской части.
- O03: недельный профиль создаёт событие только при однозначной связи group + weekday + time + date expression + discipline.
- O04: диапазон `dd.mm–dd.mm` в недельном профиле разворачивается только по указанному дню недели; явный перечень дат используется дословно.
- O05: время `hh.mm–hh.mm` и дата `dd.mm` распознаются раздельно.
- O06: несколько несовместимых времён, дисциплин или неясная принадлежность к группе => `needs_review`.
- O07: цикловой диапазон разворачивается по рабочим дням только если источник явно задаёт непрерывный цикл/лекционный блок.
- O08: праздники и исключения не зашиваются по конкретному году; поступают из metadata/calendar exceptions.
- O09: academic year, semester, program, course, group не зашиваются в parser, а поступают из source metadata и валидируются.
- O10: parser выдаёт canonical `schedule-batch/v1` либо review-required результат; ICS и коммерция вне parser.
- O11: исторические `omgmu-*` id не являются canonical `event_id`; идентификаторы назначает общее ядро versioning.
- O12: canonical timing использует floating-время; исторический offset `+06:00` не переносится в событие.
- O13: если в одной ячейке дисциплины указаны как `A / B`, а число занятий как `X/Y`, занятия распределяются последовательно: первые X подходящих дат относятся к A, следующие Y — к B. При несоответствии количества дат или иной неоднозначности — `needs_review`.
- O14: если физическая культура представлена несколькими альтернативными секциями без персональной привязки, конкретный вариант не выбирается. Создаётся нейтральное событие `Физическая культура и спорт`, а полный перечень вариантов сохраняется в `source_note`; неизвестные конкретная секция/location не выдумываются. Такой случай сам по себе не является `needs_review`.
- O18: метка курса без ссылки на файл означает, что расписание ещё не опубликовано. Watcher запускает загрузку и парсинг только при наличии фактической ссылки на файл или иного однозначного машиночитаемого источника.

## Непокрытые области

Нужно отдельно подтвердить на официальных PDF:
- лечебное дело;
- педиатрию;
- стоматологию;
- медико-профилактическое дело;
- фармацию;
- варианты цикловых таблиц;
- аудитории/корпуса/преподавателей;
- объединённые группы и подгруппы;
- дисциплины по выбору;
- осенние структуры 2026/27.

## Следующий шаг

Собрать репрезентативный набор официальных PDF разных программ/курсов, классифицировать структурные семейства и после этого проектировать production parser profiles. Исторические парсеры использовать как regression fixtures, а не как доказательство универсальности.
