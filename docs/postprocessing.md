# Постобработка расписания v1

## Назначение

Постобработка выполняется после полного парсинга, дедупликации, разрешения подтверждённых исключений и проверки нормализованного `schedule-batch` одной группы.

Она не меняет трактовку исходного XLSX/PDF. Её задача — вычислить производные данные и подготовить пользовательское представление календаря.

Реализация: `api/src/schedule/postprocess.js`.

## Входные требования

Пакет должен соответствовать `schedule-batch/v1`. Для вычисления учебной недели в `schedule.period` обязательны:

- `start_date` — начало периода расписания;
- `end_date` — конец периода расписания;
- `week1_start_date` — дата начала первой учебной недели.

Для циклового расписания парсер может заполнить `lesson.cycle_id`. Для явно совместного занятия — `lesson.joint_groups`.

## Последовательность дисциплины

События группируются по:

`lesson.discipline.normalized + lesson.type.code`.

Разные типы одной дисциплины никогда не смешиваются. Для каждой группы событий вычисляются:

- `derived.sequence.index`;
- `derived.sequence.total`;
- `derived.sequence.bucket`;
- `derived.next_same_event`;
- `derived.is_last_same_event`.

В заметках обычных учебных занятий используется формат типа `Практическое занятие · 4 из 12` или `Лекция · 2 из 6`.

Для последнего занятия дисциплины и типа выводится `Последнее занятие по дисциплине`; строка о следующем одноимённом занятии не выводится.

## Учебная неделя

`derived.academic_week` рассчитывается от `schedule.period.week1_start_date` целыми семидневными интервалами.

## Позиция занятия в течение дня

Для каждого дня события группы сортируются по времени начала. При одинаковом времени сохраняется стабильный порядок исходного массива.

В `derived.day` записываются:

- `index` — позиция текущего события;
- `total` — всего событий в этот день;
- `remaining` — сколько событий останется после текущего;
- `next_event` — ближайшее следующее событие этого дня;
- `gap_minutes` — интервал от окончания текущего события до начала следующего;
- `overlaps_next` — признак перекрытия.

Заметки содержат:

- `Занятие сегодня · 3 из 4`;
- следующее занятие и его время;
- интервал до него;
- `Осталось занятий сегодня: N`.

Интервал всегда считается от **окончания текущего занятия до начала следующего**. Если интервалы перекрываются, вместо отрицательной длительности показывается `Перерыв отсутствует: занятия перекрываются`. Для последнего события дня следующее занятие указывается как `нет`, а остаток равен `0`.

## Циклы

Если заполнен `lesson.cycle_id`, события одного цикла группируются по этому идентификатору. Номер дня цикла определяется по уникальным календарным датам.

Заполняется `derived.cycle`:

- `index`;
- `total`;
- `is_first`;
- `is_last`.

В заметках допускаются `Цикл · день X из N`, `Начало цикла`, `Завершение цикла`.

## Формы контроля

Если в самом нормализованном расписании существует конкретное событие `exam` или `credit`, постобработка может связать с ним предшествующие занятия той же дисциплины.

Заполняется `derived.assessment` с фактической датой/временем и числом оставшихся до контроля учебных занятий. Даты контроля не прогнозируются.

## Заголовок календаря

- лекция: `ЛЕКЦ. НАЗВАНИЕ ДИСЦИПЛИНЫ`;
- экзамен/зачёт: `ФОРМА КОНТРОЛЯ — НАЗВАНИЕ ДИСЦИПЛИНЫ`;
- остальные занятия: нормализованное название дисциплины;
- при наличии подгруппы/языка признак добавляется к заголовку.

## Место

`calendar.location` собирается только из подтверждённых `lesson.locations`. Неподтверждённые адреса не достраиваются.

## Порядок заметок

1. Тип и прогресс занятия.
2. Прогресс цикла при наличии.
3. Учебная неделя.
4. Следующее одноимённое занятие / последнее занятие.
5. Подтверждённая форма контроля.
6. Дневной прогресс, следующее занятие сегодня, интервал, остаток занятий.
7. Подгруппа/совместное занятие при наличии.
8. Служебный блок группы и сервиса.

Пустые или неподтверждённые сведения не заменяются заглушками, кроме специально определённого `Следующее занятие сегодня: нет`.

## Подпись сервиса

В нижней части заметок используется только согласованная ссылка:

`https://gmarkov634-stack.github.io/kirov-gmu-calendar/`

Она отделена от учебной информации и не содержит рекламного призыва.

## Промо-события

`buildPromotionEvents()` создаёт отдельные календарные события, не смешивая их с учебными занятиями.

- обычно создаётся одно нейтральное событие за 10–14 дней до конца текущего расписания; серверный default — 12 дней;
- второе событие возможно только при `nextPeriodAvailable = true` и наличии фактической даты публикации следующего календаря;
- максимум два промо-события на семестр;
- используется только согласованная ссылка проекта;
- агрессивные и повторяющиеся призывы к покупке не используются.
