# Генерация ICS v1

## Назначение

ICS генерируется только из успешно провалидированного, версионированного и постобработанного `schedule-batch`.

Поток:

`validated schedule-batch → versioning → postprocessing → ICS → стабильный подписной URL`

Реализация: `api/src/schedule/ics.js`.

Совместимость: существующий `api/src/calendar.js` автоматически направляет канонический `schedule-batch/v1` в новый генератор, сохраняя старую ветку для ранее существовавших форматов.

## UID

Каждый `VEVENT` использует:

`UID:<event_id>@<university>-calendar`

Например:

`UID:evt_123@kgmu-calendar`

UID строится только из стабильного `event_id`. Изменение даты, времени, аудитории или другого редактируемого поля не меняет UID, если versioning однозначно сопоставил событие с предыдущей редакцией.

Это позволяет календарному приложению обновить существующее занятие вместо создания дубля.

## Ревизия и SEQUENCE

Versioning хранит:

- `system.revision`;
- `system.created_at`;
- `system.updated_at`.

Новое занятие получает `revision = 1`. При фактическом изменении семантического ядра ревизия увеличивается на 1. При идентичном повторном импорте ревизия не меняется.

ICS использует:

`SEQUENCE = revision - 1`

Таким образом новое событие начинается с `SEQUENCE:0`, первое изменение получает `SEQUENCE:1` и т. д.

`CREATED` берётся из `system.created_at`, а `DTSTAMP` и `LAST-MODIFIED` — из `system.updated_at`. Они не генерируются заново при каждом HTTP-запросе календаря.

## Время

Для учебных событий используется floating local time непосредственно из `timing.date`, `timing.start_time` и `timing.end_time`.

Пример:

```ics
DTSTART:20260901T090000
DTEND:20260901T103000
```

Не используются:

- `TZID`;
- `VTIMEZONE`;
- суффикс `Z` у `DTSTART/DTEND`;
- конвертация из UTC при генерации канонического расписания.

Поэтому 09:00 из расписания остаётся 09:00 в календаре независимо от часового пояса устройства.

## All-day

Для однодневного all-day события:

```ics
DTSTART;VALUE=DATE:20261216
DTEND;VALUE=DATE:20261217
```

`DTEND` является исключающей границей и указывает следующий календарный день.

## Текстовые поля

`SUMMARY`, `LOCATION`, `DESCRIPTION` формируются из слоя `calendar`, подготовленного постобработкой.

Экранируются:

- обратная косая черта;
- перевод строки;
- точка с запятой;
- запятая.

Исходный XLSX/PDF повторно не интерпретируется на этапе ICS.

## Folding

Физическая строка ICS ограничивается 75 UTF-8 октетами. Продолжение начинается с одного пробела. Разбиение выполняется по Unicode-символам и не разрезает многобайтовый символ UTF-8.

## Стабильность выдачи

Для одной и той же сохранённой версии расписания генерация детерминирована: повторный запрос должен вернуть одинаковый ICS по содержимому.

В верхнем уровне календаря публикуются:

- `X-WR-CALNAME`;
- `X-PUBLISHED-TTL`;
- `REFRESH-INTERVAL;VALUE=DURATION`;
- `X-SCHEDULE-VERSION`;
- `X-SCHEDULE-CONTENT-FINGERPRINT`.

Default refresh hint: `PT6H`.

## Удалённые занятия

Актуальный подписной ICS является снимком текущей опубликованной версии. Событие со статусом `removed` из diff не включается в новый фид. Его прежний UID не переиспользуется для другого занятия.

Отдельные `STATUS:CANCELLED` tombstone-события в v1 не генерируются. Если при реальном тестировании конкретного календарного клиента обнаружится необходимость tombstone-механизма, он будет добавлен отдельным правилом, не меняя стабильность UID остальных событий.

## Требования перед генерацией

Генератор отказывается создавать ICS, если отсутствуют:

- `schedule.schedule_version_id`;
- `schedule.version_created_at`;
- `system.event_id`;
- положительный `system.revision`;
- `system.created_at` и `system.updated_at`;
- `calendar.title`;
- `timing.time_mode = floating`.

Это предотвращает публикацию нестабильного календаря до прохождения versioning/postprocessing.

## Regression

Тесты: `api/test/schedule-ics.test.js` и расширенный `api/test/schedule-versioning.test.js`.

Проверяются стабильный UID, floating-время, SEQUENCE, version timestamps, детерминированность, escaping, UTF-8 folding, all-day и совместимость через `buildCalendar()`.
