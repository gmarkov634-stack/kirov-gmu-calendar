## Классификация

## Новые подтверждённые частные правила

### C14 — многодневный блок «Экзамен»

В основной сетке встречаются объединённые блоки `Экзамен`, которые занимают несколько календарных дат, но не содержат одновременно конкретной дисциплины и точного времени. Такой блок является обозначением экзаменационного периода и не разворачивается в ежедневные календарные события. Конкретный экзамен создаётся только по отдельным однозначным данным с дисциплиной, датой и временем.

### C15 — дисциплины по выбору

В основной сетке встречаются `Электив`, `ДВ.4`, `ДВ.5`. Нижний справочник содержит несколько допустимых дисциплин по выбору с различающимися временем и местом. Поэтому конкретный вариант нельзя назначить автоматически только по групповой сетке. Для создания конкретного события нужна однозначная связь между блоком и выбранной дисциплиной. После её появления даты берутся из календарной сетки, а название, время и место — из соответствующей строки справочника.

## Влияние на архитектуру

`schedule-event/v1` менять не требуется: после разрешения выбора существующая модель события полностью описывает результат.

Однако C15 создаёт dependency-вопрос для пользовательского контура: если календарь 6 курса должен включать конкретные дисциплины по выбору, системе понадобится получить выбор до формирования персонального feed либо иметь другой подтверждённый источник привязки. Это следует проверить при финальном dependency-review шагов 2–12; наиболее вероятно влияние на контур выдачи/подписки, а не на canonical event schema.

До разрешения выбора конкретные дисциплины по выбору нельзя выдумывать или молча подменять одной общей альтернативой.
